# KbushubHomepage
너는 K-BUS HUB 프로젝트의 풀스택 개발자이자 UX 디자이너다.
아래 기획에 따라 실제로 작동하는 중고버스·카운티 거래 사이트를 구현해줘.
계획만 설명하고 끝내지 말고 코드 작성과 실행 검증까지 진행해줘.

[1. 사업과 목적]

브랜드명: K-BUS HUB

한국 중고버스와 현대 카운티를 전문으로 취급하며 국내 판매와 해외 수출을 함께 운영한다.

회사는 차량을 경쟁력 있는 가격에 확보할 수 있다.
사이트의 핵심 목적은 다음과 같다.

1) 국내 고객이 차량을 찾고 구매 상담을 신청한다.
2) 해외 바이어가 영문으로 차량을 확인하고 수출 견적을 요청한다.
3) 해외 에이전트가 매물을 공유하고 고객을 소개한다.
4) 회사가 재고·문의·견적·소개 이력을 관리한다.

처음에는 회사가 관리하는 매물만 등록한다.
외부 판매자 입점, 경매, 온라인 결제는 이번 범위에서 제외한다.

[2. 작업 시작]

현재 폴더와 프로젝트 지침, 설치된 기술, 기존 코드를 먼저 확인해줘.

- 기존 프로젝트가 있으면 현재 구조를 활용한다.
- 빈 프로젝트라면 Next.js App Router + TypeScript + Tailwind CSS + Supabase를 기본으로 검토한다.
- 라이브러리 버전은 설치 상태와 공식 문서로 확인한다.
- 기존 코드를 무단으로 삭제하거나 전체 재생성하지 않는다.
- 합리적으로 판단할 수 있는 UI·개발 선택은 직접 결정하고 진행한다.
- 실제 배포, 유료 서비스 신청, 운영 데이터 삭제, 외부 메시지 발송은 별도 지시 없이 하지 않는다.

먼저 간단한 계획을 설명하고 바로 구현을 시작해줘.

[3. 디자인]

깔끔하고 전문적인 자동차 쇼룸 느낌으로 제작한다.

- 흰색과 밝은 회색 배경
- 짙은 남색 글자
- 파란색 주요 버튼
- 큰 차량 사진
- 잘 읽히는 가격과 핵심 사양
- 절제된 테두리와 그림자
- 모바일 우선 반응형

과도한 그라데이션, 유리 효과, 장식용 애니메이션은 사용하지 않는다.

임시 로고는 K-BUS HUB 텍스트로 구현한다.
실제 사진이 없으면 플레이스홀더를 사용한다.
타 사이트 사진을 무단으로 가져오거나 생성 이미지를 실매물처럼 사용하지 않는다.

마이버스·헬로우버스상사의 버스 전문 정보,
엔카의 매물 탐색,
오토위니·BE FORWARD의 해외 구매 동선을 참고하되
다른 사이트의 디자인과 콘텐츠를 그대로 복제하지 않는다.

[4. 언어와 거래 모드]

언어:
- 한국어
- 영어

거래 모드:
- 국내 거래
- 수출

언어와 거래 모드는 독립적으로 선택한다.
한국어로 수출 화면을 사용할 수도 있어야 한다.

매물은 하나의 재고 데이터를 사용한다.
국내에서 판매 완료하면 해외 화면에도 반영한다.

회원가입 없이 매물 조회와 문의가 가능해야 한다.

국내 가격과 수출 가격은 별도로 입력한다.
수출 가격은 금액·통화·포함 조건을 함께 관리한다.
가격이 없으면 “가격 문의”로 표시한다.
단순 환율 계산값을 확정 수출가로 표시하지 않는다.

[5. 메인 화면]

상단 메뉴:
- 매물 보기
- 카운티
- 중형·대형버스
- 내 차 팔기
- 구매·수출 안내
- 파트너 가입
- 언어와 거래 모드

메인 구성:
1) 짧은 서비스 소개와 차량 검색
2) 카운티·중형·대형 바로가기
3) 신규 매물
4) 운영자가 지정한 추천 매물
5) 국내 구매·수출 절차
6) 원하는 차량 요청
7) 에이전트 파트너 안내
8) 회사 정보와 연락처

허구의 판매 실적, 고객 후기, 인증, 최저가 보장은 넣지 않는다.

[6. 매물 목록]

검색·필터:
- 제조사
- 모델
- 차급
- 연식
- 가격
- 인승
- 주행거리
- 수동·자동
- 연료
- 판매 상태

카드:
- 대표 사진
- 매물번호
- 모델명
- 연식·인승
- 주행거리·변속기
- 가격과 가격 기준
- 판매 상태

정렬과 필터는 실제로 작동해야 한다.
검색 조건을 URL에 반영하고 공유할 수 있게 한다.
가격 미정 매물은 가격 정렬 마지막에 둔다.
다른 통화를 근거 없이 같은 숫자로 비교하지 않는다.

로딩·오류·검색 결과 없음·사진 없음 상태를 구현한다.

[7. 차량 상세]

사진 갤러리와 핵심 정보, 가격, 문의 버튼을 상단에 배치한다.

차량 항목:
- 제조사·모델·세부 모델
- 연식·최초 등록일
- 주행거리
- 인승
- 변속기·연료
- 엔진 모델·배기량
- 좌핸들·우핸들
- 롱바디 여부
- 전장·전폭·전고
- 기존 용도
- 차량 위치
- 정비·수리 관련 확인 정보
- 알려진 결함
- 촬영일·재고 확인일

모르는 사양은 추정하지 않고 미확인으로 표시한다.

사진 분류:
- 외관
- 실내·좌석
- 계기판
- 엔진룸·하부
- 타이어
- 결함

확보된 영상 링크를 표시할 수 있게 한다.
영상은 자동 재생하지 않는다.

국내 문의:
- 구매 상담
- 방문 예약 요청
- 전화·카카오톡

수출 문의:
- 견적 요청
- 영상 확인 요청
- WhatsApp

연락처가 설정되지 않았으면 가짜 번호 대신 문의 폼을 제공한다.

판매 완료 매물은 상태를 명확히 표시하고
“비슷한 차량 요청”으로 연결한다.

모바일 하단 문의 버튼은 콘텐츠를 가리지 않게 고정한다.

[8. 문의와 견적]

로그인 없이 문의할 수 있게 한다.

문의 항목:
- 이름
- 이메일 또는 전화·메신저 연락처
- 국내·수출 구분
- 국가
- 관심 매물
- 문의 내용

수출 견적 추가 항목:
- 목적국
- 목적항: 미정 선택 가능

초기에는 운임 자동 계산을 하지 않는다.
관리자가 견적을 작성한다.

견적 항목:
- 차량대금
- 국내 운송비
- 수출 관련 비용
- 해상운임
- 보험·검사 등 기타 비용
- 통화
- 포함·제외 항목
- 거래 조건
- 유효기간
- 작성 시점·버전

미확인 비용과 실제 0원을 구분한다.
미정 항목이 있으면 확정 총액처럼 표시하지 않는다.
기존 견적은 매물 가격이 바뀌어도 원래 조건이 보존되어야 한다.

실제 저장 성공 후에만 접수 완료를 표시한다.

[10. 에이전트]

초기에는 고객 소개형으로 구현한다.

기능:
- 가입 신청
- 관리자 승인
- 승인된 에이전트 로그인
- 매물별 전용 공유 링크
- 본인이 소개한 문의의 제한된 진행 상태 조회

공유 링크에는 개인정보 대신 임의 추천 코드를 사용한다.

추천 정보는 언어·거래 모드 변경과 문의 제출 후에도 유지한다.
WhatsApp 문의 문구에는 매물번호와 추천 코드를 넣는다.

메신저 클릭을 실제 문의나 계약으로 집계하지 않는다.

추천 코드만으로 수수료를 확정하지 않는다.
중복 소개와 기존 고객 여부는 관리자가 확인한다.

최초 유입 코드와 최종 담당 에이전트를 별도로 기록한다.
변경 사유와 이력을 남긴다.

에이전트는 다른 에이전트의 고객 정보나 내부 원가를 볼 수 없다.
자동 수수료 정산은 이번 범위에서 제외한다.

[12. 데이터와 보안]

공개 매물과 내부 재무 정보를 분리한다.

권한:
- 비회원: 공개 매물 조회와 문의 제출
- 승인 에이전트: 본인에게 허용된 소개 현황
- 관리자: 운영 관리

Supabase를 사용할 경우:
- DB 마이그레이션과 RLS 작성
- 사용자가 관리자 권한을 직접 부여할 수 없게 구현
- service role 키를 클라이언트에 노출하지 않음
- 공개 이미지와 내부 자료의 접근 범위를 분리
- 문의 입력 검증과 남용 방지
- 업로드 형식·크기 제한

비밀키는 환경변수로 관리한다.
.env.example에는 자리표시자만 넣는다.
개인정보와 비밀키를 로그에 불필요하게 기록하지 않는다.

개인정보 안내·동의 영역을 준비한다.
최종 운영 정책이 준비되지 않았으면 실제 개인정보 접수를 활성화하지 않는다.

[13. 데모와 실제 운영]

외부 키가 없어도 로컬에서 화면을 확인할 수 있도록 데모 모드를 만든다.

- 샘플은 데모임을 명확히 표시
- 실제 재고나 실제 문의 접수처럼 표현하지 않음
- 데모 자료를 운영 DB에 자동 입력하지 않음
- 운영 연결 실패를 데모 성공 화면으로 숨기지 않음

샘플에는 카운티·중형·대형,
가격 미정·예약 중·판매 완료·사진 없음 상태를 포함한다.

[14. 검색과 공유]

- 모바일 반응형

미구현 기능을 작동하는 것처럼 표시하지 않는다.
